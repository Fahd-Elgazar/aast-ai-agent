# Integration and release decision

**Integration owner:** Mohammed. **Independent verifier:** teammate. P5 produces a release recommendation. A maintainer separately authorizes promotion and any deployment.

1. **Bootstrap the cleaned reference.** On the signed source build the fixture image, verify revision and health, run native gates and baseline synthetic replay, and keep a restorable image plus compatible fixture snapshot. Verify approved dataset/model availability or explicitly block missing positive controls. Record elapsed time for a baseline restore. Independent cleanup review and cleaned-stack smoke belong here.
2. **Join P1 and P2.** Fetch both complete phase refs into a disposable integration checkout. Exercise the actual planner, directed KG adapter, RAG adapter and judge on the same p1/p2 examples used by both branches. Via the normal advisor request path, also check legacy behavior. Record intermediate plan and selected/rejected ID per part. A reversed edge or borrowed week fails even if the final text reads well. Mohammed resolves caller wiring in P3; before enabling it, the lower-layer handshake must already pass.
3. **Join P3 and P4.** Run the independent oracle through the actual HTTP and browser routes. Include deterministic early return, degraded and generated replies; true and false specialized routes; CID adoption and reopened history; unsupported/missing inputs; timeout, disconnect and queue pressure. Assign each failure to the first incorrect stage. Contract drift returns to both reviewers; repeat the affected upstream and downstream gates on the integrated SHA.
4. **Freeze a P5 candidate.** Prepare CI/profile changes if needed and the two release report files on the phase branch. Commit the reports’ procedures, preliminary results and intended evidence locations before freezing the candidate SHA. Subsequent signatures, final measurement artifacts and exact commit/image identity go on the PR or release record keyed to the immutable SHA. This avoids changing the revision merely to document its own test results.
5. **Qualify and attest.** Perform NATIVE, STACK, REPLAY, FAULT and rollback as specified in [testing gates](06_TESTING_AND_ACCEPTANCE_GATES.md). The teammate independently verifies the source identity and result counts and checks evidence for all named cases, then records approval or blocker on the same SHA. A merged or rebuilt revision with a different source SHA or image digest needs its own identity check and candidate gates before it is labeled verified. A code or dependency change invalidates prior downstream approvals.
6. **Promote only the tested candidate.** Require both approvals, no unresolved P0, no missing required test, correct provenance/owner isolation, matched latency decision and a successful prior-image restore. A release PR goes to the agreed stable target. Rerun checks on its merged head; if that creates a new SHA/image, qualify it before tagging or promotion. Retain artifacts and prior digest. No tag or deploy is created by this plan.

| Failure stage | Result and owner | Recovery evidence |
|---|---|---|
| Baseline identity, missing data or model | Block comparison. Mohammed coordinates source/profile, teammate verifies fixture identity. | Both machines resolve identical identities and positive controls work. |
| Wrong referent, lost part, wrong specialized route | Mohammed fixes the earliest wrong plan/state and preserves caller compatibility. | Failing exact turn followed by correct next turn on same CID; valid golden case preserved. |
| Right plan, wrong fact, missing chapter or unsupported claim admitted | Teammate inspects graph match, RAG recall/rank and per-part adjudication. | Correct ID selected or precise absence reason; matched negative rejected. |
| Correct adjudication, wrong public answer/citation or late state write | Mohammed fixes deterministic/synthesis/formatter/UI or lifecycle path. | HTTP, React, legacy payload and abort tests green. |
| Failed rollback or irreproducible timing | Withhold release. Restore prior compatible image + snapshot in isolation and compare warm profiles. | Health probes, three-turn CID, baseline fingerprints and measured restoration time. |

If a phase must be undone, stop the merge queue. Identify transitive consumers in the dependency graph. For a cross-lane contract break, disable/revert dependent public wiring before reverting its provider; preserve user data and retain failure artifacts. Use a reviewed revert PR, rerun the same gates and announce the new known-good SHA. A deployment reversal uses the recorded prior digest and compatible stores; do not delete volumes or reset branches.
