# Shared interface freeze

This is the proposed v1 agreement for FREEZE. Capture the reviewed examples and limits on the approved code baseline before implementation. All items below have one change owner. A change requires a producer fixture, a consumer fixture, a compatibility decision, a version note and approval by the other developer. Append optional internal fields in v1. Breaking changes require a new version, parallel readers, a migration/rollback test and explicit acceptance. Keep public coverage internal unless both approve an additive field.

## Freeze examples both agents must consume

Use synthetic values; source locators below illustrate fixture identities. Install matching fake producers and consumers or compare serialized producer output. Public examples should continue to use the existing HTTP fields.

```json
{
  "version": 1,
  "requestId": "fixture-turn-1",
  "parts": [
    {"partId":"p1","goal":"syllabus","subjects":["Cognitive Computing"],"relation":"syllabus_week","timeScope":{"week":3},"intent":"syllabus","slotOrigins":{"subject":"explicit","week":"explicit"},"evidenceRequirement":"course-week"},
    {"partId":"p2","goal":"syllabus","subjects":["NLP"],"relation":"syllabus_week","timeScope":{"week":4},"intent":"syllabus","slotOrigins":{"subject":"explicit","week":"explicit"},"evidenceRequirement":"course-week"}
  ],
  "unresolved": []
}
```

For this example resolve p2 first in the fake adapter. Give p1 an approved fixture passage and p2 only a neighbor's week. The judge must return p1 supported with its passage ID, p2 missing with a scope-mismatch reason, in original order. Formatter must not use p1 to fill p2. Repeat with both parts valid and a legacy single-string request. For A01/4 the subject is inherited Data Science, the explicit relation is inclusion of Machine Learning, and the prior careers goal is ineligible. For a cleaned-source positive that already passes, preserve the assertion and record the verified path.

## Shared interface freeze checklist

- [ ] Both accounts fetch the approved source, cleanup parent and reviewed clean commit. Capture exact tracked blob IDs and line-ending policy.
- [ ] Identify each actual producer/consumer above, including bypass routes and persisted/reopened sessions. Run one old-format input/output for each boundary.
- [ ] Approve the example serialization, typed subject representation for IDs and unresolved names, part cap and overflow behavior, status/reason vocabulary, optional field defaults, score ranges/units and ID uniqueness scope.
- [ ] Sign examples for two parts, explicit correction, ambiguous subject, genuine absent evidence, conflict, abort and legacy envelope. Keep both positive and negative evidence fixtures independent of the implementation's scorer.
- [ ] Freeze queue/concurrency, warm-up, per-stage bounds, remaining-budget unit and retry rules. Agree trace field allowlist, record size, retention and disabled behavior. Record concrete values with the fixture profile.
- [ ] Verify schema compatibility and consumer snapshots. Record review ref, accepted SHA, example hash and owners in the P0 freeze. Both reviews are required to alter a shared contract thereafter.
